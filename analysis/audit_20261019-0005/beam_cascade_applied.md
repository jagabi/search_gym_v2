# d3 자동 빔 탐색 및 문서 선별 적용

2026-10-19. 기존 beam 구현을 활성화하고 파라미터 및 실제 평가 프롬프트를 조정했다. 탐색 제어 알고리즘을 새로 추가하지 않았다. 메인 모델의 연구 도구는 web_search 하나이며, 페이지/링크 평가와 후속 확장 및 문서/번들/청크 선별은 d3가 담당한다.

## 확정 적용값

| 항목 | 값 |
|---|---|
| traversal / expected traversal | beam / beam |
| 검색 상한 | 10 |
| HTTP 웨이브 | 판정 1개씩 4개 요청, 전부 완료 후 다음 웨이브 |
| 초기 페이지 | 6 |
| 부모별 링크 후보 | 최대 2 |
| 다음 깊이의 전체 방문 | 최대 2 |
| 링크 점수 하한 | 0.10 |
| 깊이 / 검색당 총 방문 | 최대 3 / 10 |
| 전체 본문 청킹할 페이지 | 모든 깊이에서 합계 최대 2, 원질문 1 + 질의 1 |
| 페이지 미리보기 | 5000 토큰 유지 |
| 청크 / 번들 | 512 / 5000 토큰 유지 |
| 번들·청크 하한 | 0.15 유지 |
| 반환 청크 top-k | 원질문 4 + 질의 8 유지, 인접 청크 문맥은 별도 포함 |
| 강제 최종 재작성 | 비활성화 |

6 → 2 → 2는 상한이다. 하한을 통과하는 링크가 없으면 다음 깊이를 채우지 않고 끝난다. 초기 검색 결과가 6개 미만이면 그만큼만 시작한다. 검색별 10페이지에는 실패 및 재사용 노드도 포함한다. 20분 문제 타임아웃은 추가하지 않았다.

선택된 문서 2개의 전체 원문은 기존 Docling 청킹을 사용한다. 모든 방문 문서를 청킹하지 않는다. 선택 문서의 번들을 평가하고, 선별된 번들의 청크를 평가한 뒤 반환할 청크를 고른다. 반환 top-k는 청크 평가 요청 수의 상한이 아니다. 각 문서가 최종 발췌를 반드시 하나씩 받는다는 보장도 없다.

## 프롬프트

- 메인: 질문의 실제 단서로 검색하고 확인하지 않은 추측으로 질의를 좁히지 않으며, 반례에 따라 질의를 수정하도록 명시했다. 연도·단위·범위를 구별하고, 접근 불가 원문은 제목/저자 등으로 대체 출처를 검색한다. 별도 읽기·확장 도구나 연구 상태 제출은 없다.
- 페이지 평가: 해당 페이지 자체의 원문을 읽을 가치와, 그 페이지의 외부 링크가 유용한지를 구분한다.
- 링크 평가: 구체적인 중간 관계·원문·반박 근거를 인정하고, 부모 페이지가 직접 답을 담지 않았다는 이유만으로 경로를 낮게 평가하지 않도록 했다. 단어 반복/일반 메뉴는 사실 근거로 취급하지 않는다.
- 원문 평가: 사실의 주체·날짜·측정 단위와 의미를 보존한다.
- 평가 프롬프트 변경이 기존 응답 캐시와 섞이지 않도록 RawTree 버전을 `raw-browser-beam-cascade-docling/11`로 올렸다.

## 검증

전체 오프라인 테스트 270개 통과, 실패/오류 0개. 상세: beam_cascade_validation.json.

새 통합 검사에서 다음을 확인했다.

1. 초기 6개에서 부모별 후보들을 비교해 전역 상위 2개만 다음 깊이로 확장하고, 그다음도 최대 2개만 방문한다.
2. 모든 방문 페이지 중 초기 root 한 개와 depth 3 문서 한 개를 점수에 따라 선별한다. 이 두 문서만 번들/청크 평가에 진입한다.
3. 0.099 링크는 확장하지 않고 0.10은 허용한다. 예산이 남아도 미달 후보로 채우지 않는다.
4. 유효 정책의 메인 도구는 web_search 하나이며 progressive 연구 상태 및 강제 최종 검토는 비활성화 상태다.

실제 모델의 정확도와 10문제 소요시간은 아직 새 설정으로 재측정하지 않았다. 기존 progressive 실행의 55분은 이번 자동 빔 탐색의 예상시간으로 쓰지 않는다.

## 기존 10문제 실행

가상환경이 활성화된 프로젝트 루트에서 실행한다.

```powershell
python test.py --method jevtree --model gpt-oss --benchmark browsecomp --path data/browsecomp/test_diagnostic10.json --limit 10 --raw-traversal beam --expect-raw-traversal beam --tag raw_browser_p11_beam10 --no-cache
```

이전 progressive 실행 명령 대신 위 명령을 사용한다. 기본 기대 정책도 beam이므로 한쪽 traversal만 다른 값으로 덮어쓰면 시작 전에 불일치로 차단된다.
