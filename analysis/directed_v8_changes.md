# v8 적용 내용

2026-09-24. v7 동일 77문항 분석을 바탕으로 DS relational 경로만 변경했다.
실제 모델/검색/fetch/judge 호출은 실행하지 않았다.

## 무엇을 바꿨나

| 문제 | 구현 | 기대 범위 |
|---|---|---|
| 403 이후 문서 제목·저자 단서 소실 | 이번 검색 배치의 sources는 유지, selectable만 축소. 실패 반환에도 title/snippet/접근 상태 포함 | 같은 문서의 다른 사본을 찾을 단서 보존 |
| 루트 및 자식이 원 질문 전체를 다시 해결 | 직전 메인의 판단 + 진입 선택 이유를 루트 navigation에 전달. 자식은 링크 목적 → 부모의 선택 이유 → 상속 작업 순서 | 구체적 과제 전달; 모델이 이를 따르는지는 별도 검증 필요 |
| 추출에서 선택한 첫 링크를 별도 호출로 다시 선택 | Expand yes 및 명확한 Next links가 있으면 첫 실행 가능한 URL을 기존 _open으로 실행 | 해당 페이지의 첫 탐색 LLM 호출 1회 제거 |
| 탐색 판단마다 원문 전체 재입력 | 전체 원문은 추출 때 읽고, 이후는 저장 근거 + 모든 관측 URL의 주변 문맥 사용 | 탐색 입력 비용 감소; 잘못 추출한 근거가 자동 교정되는 것은 아님 |
| 접근 화면을 긴 연구 노트로 생성 | 알려진 접근 화면만 있는 경우 모델 없이 짧은 상태 반환. 실제 본문/다른 링크는 일반 독해 | 명백히 근거 없는 화면 비용 절감 |
| 각 페이지의 전체 미확인 목록 중복 | Missing은 원래 출처 노트에 유지하고 반환 앞부분에는 중복하지 않음 | 입력 중복 감소 |
| 임의 연도와 후보 고착 | 메인·진입 프롬프트에 원 질문 기준 후보 비교, 반증, 실패 문서 대체 사본 우선 명시 | 정책 개선이며 정확도 보장/기계적 검증 아님 |

## 재귀 동작

1. 메인이 검색하고 진입 reader가 기존 web_fetch(url)로 문서를 선택한다.
2. 문서 reader가 원 질문과 현재 원문만 보고 근거와 Next links를 출력한다.
3. Expand yes의 첫 명확한 실행 가능 링크는 모델이 이미 선택한 경로로 취급한다.
   코드는 순위를 새로 계산하지 않는다. 형식이 모호하면 기존 native fetch 판단으로 돌아간다.
4. 기존 URL/동일 사이트/중복/깊이/노드/자식 제한을 적용해 자식을 실행한다.
5. 자식 근거를 받은 부모는 다시 판단해 다른 자식을 읽거나 종료한다.
6. 진입 reader는 다른 형제 문서를 읽거나 종료하고, 메인이 다시 호출된다.

노트에서 실행된 경로를 native tool-call 응답처럼 꾸미지 않는다. trace의
`expand.from_note`와 부모 대화의 설명으로 구분한다. 후속 native 호출의 url 스키마는 같다.
`explorer.request`를 추가해 이후 실제 읽기 단계별 시간을 분해할 수 있다.

## 통제 및 한계

- 검색 10회, 결과 10개, depth 3, 재귀 12노드, 자식 2개, 루트별 확장 6개 그대로.
- 검색당 진입 1페이지 제한 없음. 기존 main/entry/reader 턴 상한 그대로.
- RAgent/search-o1의 정책·모델 설정·캐시 버전은 그대로.
- DS 캐시만 `agent/46-ds-directed-reading`으로 변경. v7 실행에 resume하지 않고 새 태그 사용.
- 별도 verifier, 상태 갱신 모델, 새 외부 도구 없음. task 전달은 새 필수 tool 인자를 쓰지 않음.
- 전체 방문량 감소는 모델 선택에 달려 있다. 전체 latency/accuracy 개선율은 아직 모른다.

## 검증

오프라인 테스트 144개 통과. 첫 경로 실행, 부모의 후속 선택, 3단계 재귀, 깊이/예산
소진, 실패 예산 반환, 근거 보존, navigation 가설의 extraction 비유입, 실패 metadata
보존, 접근 화면과 실제 본문 구분, baseline 캐시/도구/최종화 기존 회귀 검사를 포함한다.
두 자식을 읽는 고정 응답 시나리오는 추출 3회 + 부모 판단 1회 = 4회이며,
종전 별도 첫 확장 판단을 포함한 동일 시나리오 5회에서 1회 줄어든다.
이는 벤치마크 속도/정확도 측정이 아니다.

우선 실행:

```sh
python test.py --benchmark browsecomp --split test --limit 10 --method depthsearch --tag ds_directed_v8
```

10문항에서는 정답률 우열보다 문항당 모델 호출·latency·무효 호출·새로운 재귀 경로와
빈 최종 답 발생 여부를 먼저 확인한다. 비용 감소 없이 full run을 반복하지 않는다.
