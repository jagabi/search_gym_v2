# JevTree 실제 구조화 점수 분석

스냅샷: 2026-10-02T19:22:49.825335+09:00

범위: 완료 6문항(q3/q7/q8/q13/q15/q21). API 원본 answers JSON은 저장되지 않았다. trace의 entry_scores, evidence, top_links(상위 8개)와 explorer.json의 실제 자식 링크 점수·독해 여부를 연결했다. 원래 link_i 번호와 9위 이하의 전체 점수는 복원할 수 없다.

3개 이상 링크가 있는 부모 319개에서 2위와 3위 점수 차이 중앙값 0.02. 250개(78.4%)는 차이 0.05 이하. 고정 분기 3→2가 유리하다는 결론은 이 분포에서 나오지 않는다.

## 실제 성공한 자식

실패·중복을 제외한 세 번째 성공 자식은 261개, 그중 reader가 선택한 페이지는 34개. 원래 링크 점수 3위와는 다를 수 있다. q7 Tom Wopat 페이지에서는 3위 Alicia Witt 링크 점수 0.72 → 자식 근거 점수 0.86 → reader 선택이었다. 모든 완료 문항이 오답이므로 이것을 정답에 기여한 근거라고 해석하면 안 된다.

## 링크 점수와 열린 자식의 점수

| 사전 링크 점수 | 성공 자식 수 | 사후 근거 점수 중앙값 | 근거 ≥0.15 | reader 선택 |
|---|---:|---:|---:|---:|
| 0 ≤ s < 0.05 | 83 | 0.010 | 0 | 0 |
| 0.05 ≤ s < 0.15 | 172 | 0.030 | 10 | 4 |
| 0.15 ≤ s < 0.3 | 207 | 0.060 | 59 | 21 |
| 0.3 ≤ s < 0.5 | 144 | 0.225 | 87 | 28 |
| 0.5 ≤ s < 1.0 | 264 | 0.420 | 213 | 83 |

최종 구간에는 1.0을 포함한다. 이 통계는 열린 페이지에 한정되므로 방문하지 않은 후보의 품질이나 전체 확률 보정 성능을 측정하지 않는다.

## 저장된 경로를 점수로 잘랐을 때

| 링크 하한 | 잘리는 경로의 fetch 시도 수 | 잘리는 기존 reader 선택 페이지 |
|---|---:|---:|
| 0.05 | 131 | 0 |
| 0.1 | 216 | 1 |
| 0.15 | 347 | 4 |

위 표는 실제 저장된 트리에서 낮은 점수의 간선과 후손을 제외한 사후 집계다. 정책을 바꾸면 대체 링크, 방문 중복, 이후 검색어가 달라지므로 재실행 성능/비용 예측이 아니다. 0.05 하한은 관측 경로의 131/1363=9.6% 시도를 제외하면서 기존 독해 선택을 보존하지만, 이 표본 밖에서 안전하다는 보장은 없다.

## 판단 수정

고정 분기 축소를 먼저 제안한 것은 성급했다. 현재 관측은 순위만으로 3번째를 제거하기보다 매우 낮은 절대 링크 점수 구간을 별도로 검토할 근거를 준다. 부모 본문 근거 점수가 낮아도 자식에서 높은 점수가 나오는 사례가 있으므로 부모 evidence만으로 자식을 막는 것 역시 지지하지 않는다. 설정과 실행 코드는 변경하지 않았다.
