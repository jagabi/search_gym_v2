# p13: 원문 범위를 보존하는 보완 독해와 관계 중심 판정

2026-10-20. 대상은 `jevtree / raw / beam`이다. 메인 reasoning은 d3에 전달하지 않는다. 새 검색기·메인 도구·요약 모델을 추가하지 않았다.

## 변경

1. `rawtree.py`의 페이지 카드가 최초 평가에 사용한 최대 `jev_page_tokens` 원문 prefix를 그대로 보존한다. 기존처럼 다시 앞부분 600토큰으로 줄이지 않는다. 후보뿐 아니라 이미 고른 페이지도 같은 원문 범위로 비교하므로, 뒤쪽 표/후보를 놓치거나 이미 있는 사실을 새 사실로 판단하는 입력 손실을 줄인다.
2. 보완 독해 판정은 단순한 다른 소개가 아니라 현재 목표 관계, 조건에 맞는 대안 후보, 같은 가정에 대한 반증을 평가한다. 기존 단독 점수와 보완 점수를 곱하지 않고 조건부 보완 판정을 우선한다. 동점에는 기존 점수를 사용하고, 판정 실패에는 기존 점수로 대체하며 실패 이벤트를 남긴다.
3. 보완 판정에도 기존의 정확한 state/questions 기반 판정 캐시를 사용한다. query·원문·선택된 페이지·판정 문구가 바뀌면 다른 키가 된다.
4. raw의 진입/페이지/문서 구간/최종 근거 판정 문구를 후보-연결 관계, 대안 후보, 주체·시점·측정 정의 구분에 맞춘다. `direct_answer`, `query_answer` 키는 로그/선택 호환성을 위해 유지하고 판정 value의 의미를 수정했다. 링크 판정 문구는 과거 후보 변경의 순위 악화 기록을 고려해 기존 것을 유지했다.
5. 메인 프롬프트는 문헌 발견 후 누락 관계 확인, 제목/저자/식별자를 이용한 대체 원문 검색, 미확인 숫자·장소·직업의 제한 조건 승격 방지, 시대 모순 검토, 출처 간 속성 혼입 방지에 맞췄다. 최종 답은 근거 없는 부가 설명으로 모든 단서를 맞추지 않도록 했다.
6. raw 버전을 `raw-browser-d3-navigation-docling/13`으로 올렸다. 기존 runner가 이 버전을 캐시 fingerprint에 포함하므로 p12 응답 캐시와 구분된다. 보완 선택 후보별 단독 점수·선택 점수는 `rawtree.read_selection`에 기록한다.

## 비용과 한계

검색 10회, 결과 10개, 루트 6개, 깊이 3, 방문 10개/검색, 원질문 1+쿼리 1 독해, beam 폭 2, 요청당 key 1개와 strict wave 4개는 유지한다. 전체 문서 청킹/독해는 선택된 두 페이지에서 수행한다. 추가적인 원문 선별 모델 호출을 만들지 않고, 기존 보완 평가에 들어가는 원문 범위만 보존했다.

따라서 요청당 입력은 늘어난다. 현재 기본값에서 두 페이지를 비교할 때 원문 prefix만 최대 약 10,000토큰이며, 질문·메타데이터·판정 지시는 별도다. 추가 읽기 슬롯이 생긴 것은 아니다. 실제 서비스의 입력 한도·지연·정확도는 서버 실행으로 확인해야 한다.

이 변경은 최초 5,000토큰 밖의 모든 근거를 페이지 선택 단계에서 보여주는 방식이 아니다. 긴 문서의 기존 구간 트리 탐색은 본격 독해 단계에서 유지되며 표본 누락 가능성은 남는다. HTTP 422로 읽지 못한 원문을 복구한 것도 아니다. 10/10 달성이나 정확도·속도 개선을 검증했다고 주장하지 않는다.

## 확인 상태

- 변경한 Python 파일은 실행/import 없이 AST 문법 검사했다.
- 변경 diff의 공백 오류를 확인했다.
- 600토큰 뒤 후보/기존 관계 보존 및 단독 점수 곱셈으로 대안 후보를 잃는 경우에 대한 회귀 테스트 2개를 추가했다.
- 로컬 단위 테스트, 모델 호출, replay, benchmark는 실행하지 않았다. 로컬 번들에 PyYAML이 없어 YAML parser 검사는 수행하지 못했다. 설정에서는 기존 scalar 값은 유지하고 주석과 literal block 프롬프트만 변경했다.

## 서버 실행

프로젝트 루트에서 최근 동일 10문항을 새 태그로 실행한다. 기본 `conf.yaml`의 method는 `depthsearch`이므로 `--method jevtree`를 명시해야 한다. 메인 endpoint와 d3/reader 배포 설정은 서버 환경의 기존 설정을 사용한다.

```bash
python test.py --method jevtree --model gpt-oss --benchmark browsecomp --path data/browsecomp/test_diagnostic10.json --limit 10 --raw-traversal beam --expect-raw-traversal beam --tag raw_browser_p13_relations10
```

중단 후에는 같은 명령 뒤에 `--resume`을 붙인다. p12 실행 폴더를 지정해서 이어 돌리지 않는다. 서버에서 회귀 테스트를 별도로 확인하려면:

```bash
python -m unittest discover -s tests -p "test_raw*.py" -q
```
