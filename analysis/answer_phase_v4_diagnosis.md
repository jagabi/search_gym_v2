## 1. 가장 큰 병목: fetch 전용 단계가 아직 정상적으로 작동하지 않는다

선택 호출 2,815회 중 실제 fetch 1,212, 정상 생략 73, 실패 1,530이다.
실패율은 54.35%다. 실패 세부:

| 원인 | 횟수 |
|---|---:|
| 검색 엔진 쿼리 URL | 659 |
| 그 밖의 미등록 URL | 480 |
| 이미 읽은 URL 재선택 | 358 |
| 이미 실패한 URL 재선택 | 18 |
| URL 대소문자/끝 슬래시 차이 | 5 |
| 잘못된 호출 | 1 |
| 빈 응답 | 4 |
| 길이 제한 종료 | 5 |

대부분은 파싱 실패가 아니다. 모델이 주어진 미방문 페이지를 고르지 않았고,
현재 코드는 거절 후 내부 단계에 재판단 기회를 주지 않고 메인으로 복귀한다.

현재 선택기 입력은 이번 검색 10개뿐 아니라 이전 미방문 결과·발견된 링크·작업
상태 전체를 포함한다. 선택 후보 중앙값 40개, 최대 143개. 입력 중앙값 25,298자,
최대 71,571자다. 작업 상태에는 이미 읽은 출처 URL도 있다. 선택 후보가 1–10개인
329회에서는 invalid 122회, 11–30개인 681회에서는 341회, 31개 이상인 1,805회에서는
1,067회였다. 난이도·진행 시점도 섞여 있어 메뉴 크기의 인과 효과를 추정한 값은 아니다.

### 권장 구조

검색 결과를 하나의 fetch 전용 세션에 넘긴다. 이번 검색의 미방문 결과는 title,
정확한 URL, snippet을 유지한다. 이미 읽은 출처의 전체 URL 목록을 다시 선택 메뉴에
넣지 않고, 해당 사실은 짧은 출처 연결 노트로 보존한다. 과거 미방문 후보는 버리지
않되 현재 선택 메뉴와 분리한다. 현재 질의도 함께 전달해 어떤 단서를 찾는 중인지
알려주며, 질의에 들어간 가정은 출처 사실과 구분한다.

같은 세션 안에서 fetch 결과를 받은 뒤 다른 진입 페이지를 읽거나 일반 응답으로
종료하도록 한다. 잘못된 호출은 같은 세션에 명확히 알려 재판단할 수 있게 하고,
기존 bounded tool recovery 원칙을 사용한다. 무제한 재시도는 추가하지 않는다.
depth 1의 추가 fetch 때문에 web_search를 다시 소비하는 결합을 해제하는 것이 목적이다.
실제 추가 문서/모델 비용은 별도로 기록해야 한다.

선택 URL은 알려진 후보 중 하나여야 한다. URL 자유 생성 대신 제공한 후보만
출력하도록 입력/도구 스키마를 구성하고, 서버가 지원한다면 생성 단계 제약도
검증한다. 스키마에 enum을 썼다는 사실만으로 강제가 보장된다고 가정하지 않는다.
검색 엔진 URL을 허용해 invalid 수를 낮추는 방식은 검색 10회 통제를 훼손한다.

## 2. 쿼리가 질문에 없는 조건을 만들어 내고, 조건의 대상을 바꾼다

### q00660 — '다른 도구'가 'computer'로 변함

원 질문은 두 암살 사건 사이의 시기에 다른 도구를 권유받은 인물이다. 첫 쿼리는
`computer`, `1965`, `25th anniversary 2018`을 이미 특정해 검색했다. 이후에도
University of Ghana, 특정 개관 연도를 사실처럼 좁혔다. 첫 fetch는 컴퓨팅 역사
PDF였고, 이후 fetch 전용 단계에서 검색 엔진 URL을 6번 제출해 거절됐다.
o1의 정답은 Ablade Glover, v4는 식별 불가였다.

### q00852 — 논문 연도가 수상 연도로 이동

질문에서 2015는 MIT 논문 제출 연도다. 하지만 네 번째 쿼리는
`INFORMS President's Award 2015`였고, 모델은 그해 수상자인 Jack Levis를 추적했다.
후에 전체 수상자 목록을 읽어 정답 Richard C. Larson(2003 수상)도 노트에 보존했지만,
메인은 Jack Levis를 답했다. 이것은 연도 계산 오류가 아니라 서로 다른 관계의
조건을 잘못 묶은 사례다. 모델 자체를 바꾸지 않고도 질의 정책에서 다룰 여지가 있다.

### 권장 정책

모든 단서를 한 검색어에 합치지 않고, 식별력이 높은 한 관계를 먼저 검색한다.
날짜·수치·직업 조건은 원 질문에서 수식하는 대상에만 붙인다. 후보 이름이나
정확한 연도는 질문 또는 읽은 출처에 근거가 있을 때만 검색 조건으로 사용한다.
이는 기존 정책을 긴 체크리스트로 늘리기보다, 위 두 종류의 짧은 일반 예시와 함께
명확히 표현하는 편이 낫다. 계산기·추가 모델·검색 한도 변경은 필요 없다.

## 3. 출처를 골라도 키워드 복제 페이지에 빠진다

q00666은 책의 큐레이터가 거주한 도시를 찾는 문제다. 실제로 읽은 페이지 5개는
URL 제목에 Lifetime Muzzle Award·blackout 같은 검색 단서를 길게 반복하는
ebook/PDF 경로였다. 입력된 도메인/경로는 도시·책·큐레이터의 출처 맥락을 거의
설명하지 않는다. 원문 진위를 전부 검증한 것은 아니므로 모두 스팸이라고 단정할
수 없지만, 검색어 일치만으로 선택한 취약성이 드러난다.

q00326은 이번에 Baby를 맞혔다. 결정적 흐름은 Kidlit411 인터뷰에서 작가를 찾고,
작가 본인 사이트의 bio/books/babycomeout 페이지로 재귀한 것이다. 재귀를 늘리는
것 자체보다, 이런 출처 관계가 있는 입구를 선택하는 것이 중요하다.

출처 선택은 제목의 단서 일치와 함께 저자/기관/출판사/문서 종류가 질문의 관계를
실제로 입증할 수 있는지를 봐야 한다. 특정 도메인 블랙리스트를 계속 덧붙이기보다는
일반적인 출처 맥락을 기준으로 한다. baseline의 공통 필터를 바꾸는 제안은 아니다.

## 4. 최종 답변을 더 공격적으로 만들기만 해서는 부족하다

오답 중 정답 문자열이 reader 노트에 등장한 문항은 단순 문자열 기준 7개였다:
q00074, q00495, q00609, q00635, q00787, q00852, q01073. 숫자/일반 명칭의 우연한
등장도 포함할 수 있어 '확보한 정답 7개를 잃었다'는 뜻은 아니다.

q00495는 B.O.B.라는 후보를 찾았지만 인터뷰를 9번째 검색에서야 읽었다. 마지막
검색은 Urban Strike였다. 필요한 무기/게임 엔진 조건을 B.O.B.에 연결해 확인하지
못했다. 출력 단계에서 무조건 후보를 선택하게 하는 것보다, 후보를 찾은 시점에
남은 조건을 확인할 독해 기회를 주는 편이 원인을 직접 겨냥한다.

후보 상태 JSON 갱신도 1,000회 중 411회 실패했다(빈 본문 369, 비정상 본문 29,
길이 제한 13). 마지막 상태에 후보가 있는 문항은 64개, 잠정 답이 있는 문항은
32개였다. 추가 상태 관리 로직을 더 붙이기보다 선택/독해 연결부터 안정화하고,
이 보조 호출은 비용 대비 가치와 역할 중복을 재검토할 대상이다.

## 다음 변경 범위와 검증

1. 종료 경로는 유지한다. 40턴·깊이·검색 10회·결과 10개를 늘리지 않는다.
2. fetch 전용 단계를 실제 대화 루프로 만들고, 선택 입력의 중복과 행동 범위 혼동을 줄인다.
3. 메인 질의 정책은 한 관계씩 검색하고 조건의 대상을 보존하도록 짧게 정리한다.
4. 기존 실행에서 고른 정상 선택·범위 이탈·좋은 링크가 없는 입력을 동일하게
   재생해 비교한다. invalid 감소뿐 아니라 엉뚱한 페이지를 고르는지, 불필요한
   fetch가 늘었는지도 확인한 뒤 전체 실행한다.

추가 재귀 노드는 472개, 재귀를 사용한 문항은 149개, depth 3은 78개다. 현재
정답 38개 중 22개가 재귀를 사용했다. 문항 난이도와 탐색 선택이 섞이므로 재귀의
인과 효과를 추정하는 수치는 아니다. 노드 예산 12개를 소진한 문항은 3개뿐이다.
다음 개선의 중심은 더 깊이 파도록 강제하는 것이 아니라, 확보한 검색 결과에서
실제로 유용한 페이지와 그 후속 링크를 읽도록 연결하는 것이다.
