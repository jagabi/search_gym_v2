- **실제 설정: `jev_traversal=best_first`**. progressive 흐름은 실행되지 않았다.
- 주 모델에 노출된 도구는 `web_search` 하나. `research_state=null`, `finalize_answer=false`.
- d3: 요청당 질문 1개, 한 웨이브 4개. 전 문항 최대 동시 요청 4, 이전 웨이브와 다음 웨이브 중첩 0.

- 페이지 읽기 direct 2 + query 4; 청크 direct 4 + query 8; 링크 최소 점수 0.
- 현재 로컬 기본 설정은 progressive지만, 저장된 실행 설정은 best_first다. 실행 당시 설정 파일과 CLI 중 어느 것이 원인인지는 저장 로그만으로 확정할 수 없다. CLI `--raw-traversal`은 YAML 설정을 덮어쓴다 (`searchgym/config.py:281`).

## 일이 늘어나는 코드 구조

`RawTree.run`의 `best_first` 분기는 페이지 평가/링크 평가를 수행하는 작업을 4개씩 활성화하고, 빈자리를 frontier의 최고 점수 페이지로 채운다 (`searchgym/rawtree.py:390`). 페이지 방문 50개 또는 frontier 소진까지 이 과정을 반복한 **뒤에** `_read_rows`를 호출한다 (`:439`, `:446`).

64회 검색 중 **55회가 정확히 50페이지 한도를 소진**했다. 나머지는 빈 검색 5회 및 3/2/1/1페이지 검색이었다. 50이라는 값이 사실상 매 검색 목표량처럼 작동했다. 답 근거가 일찍 있어도 주 모델이 중간에 받아보고 검색을 멈추거나 방향을 바꿀 수 없다.

`jev_branch=2`, `jev_frontier_width=10`은 beam 분기에 적용된다 (`:371`, `:375`). best_first의 부모별 top-k 제한으로 작동하지 않는다. 실제 best_first는 전역 우선순위와 방문 한도를 사용한다. 링크 점수 0은 확장을 차단하지 않는다. 하지만 임계값만 높여도 이미 열린 페이지의 링크 평가 비용은 발생한다.

516번은 173.2분 동안 링크 20,334개를 평가했다. 검색 4번(The Constant Gardener cast)은 링크 5,236개/44.1분, 검색 5번(잘못 떠올린 감독 Corbin Bernsen)은 4,199개/37.4분이었다. Apple TV 국가별·영화별 메뉴에서 페이지당 약 199~200개 링크가 평가된 사례가 있다. 1230번에는 Reddit 연도별 목록 페이지당 200~201개가 있었다. 링크 개수가 많다는 사실이 질문 해결에 유용하다는 뜻은 아니다.

낮은 링크 점수만이 전부는 아니다. 516번 확장 페이지 360개 중 점수 0.1 미만은 6개뿐이다. 같은 임계값 아래는 598번 91/162, 746번 80/364, 1230번 103/404다. 저점수 가지치기는 일부 낭비를 줄일 수 있으나, 잘못된 검색 목표에 높은 점수를 받는 가지는 계속 남는다.

## 오답 원인

### 598: 논문 → Romanian Statistical Review

검색 2번에서 학술지 사이트의 PDF 후보와 Elisabeta Jaba 감사 문구가 이미 검색 결과에 들어왔다:

`https://www.revistadestatistica.ro/wp-content/uploads/2014/01/RRS_10_2013_a1en.pdf`

14.13분 fetch 결과는 논문이 아니라 `Verifying your browser... / Enable JavaScript and cookies to continue!`였다. `is_error=false`, metadata title도 인증 화면이다. 따라서 HTTP/Reader 성공과 실제 논문 확보가 구별되지 않았다. 모델이 전달받은 검색 스니펫에는 Jaba와 감사 문구가 있었지만 본문을 재확보하는 방향으로 이어지지 않았다.

검색 2~10번의 9회가 같은 연구센터/도시/책임자를 중심으로 반복됐다. 더 식별력 있는 `HDS test`, `2007-2012`, `Table 3`를 실제 검색하려 한 것은 11~13번째 도구 호출에서였고, 이미 검색 10회 한도를 써서 **전부 거절**됐다. 이 실행에서 정확한 논문 본문을 확보했다고 볼 수 없다. 유력 주소 발견 → 차단된 본문 → 복구 없이 주변 검색 반복 → 핵심 단서 검색 전에 예산 소진의 연쇄다.

### 746: 인물의 청소년기 체류국 → Japan

70.55분 반환 자료에 Nelson Rockefeller의 부통령 경력, 출생일 1908-07-08, 출생지 `Bar Harbor, Maine`이 들어 있다. 하지만 다음 모델 단계는 Hannibal Hamlin을 유일한 Maine 출신 부통령으로 단정했다. 모델은 동시에 **Hamlin이 1891년에 사망했고 Person A는 1930년대 출생이라 보좌관 근무 연결이 부자연스럽다**는 점까지 스스로 언급했다.

그 모순을 후보 탈락으로 반영하지 않고 나중에 `Minnesota born 1935 worked for Hannibal Hamlin aide`를 검색했다. 필요한 대안 후보의 단서는 읽기 계층에서 전달됐지만 모델의 후보 갱신이 실패했다. Japan이라는 단어는 다른 인물의 대사 경력 등에도 나오므로 단순 문자열 출현을 정답 증거로 취급하지 않았다. Person A의 해당 체류를 입증하는 근거는 이번 감사에서 확인하지 못했다.

### 1230: 영화관 → Regal Cinema

초기 검색 이후 도시의 교통 수치만 반복해서 검색했다. 여러 쿼리가 사용자가 지정하지 않은 INRIX에 고정됐고, 215/225/200시간 등 조건과 다른 값도 검색했다. 영화관 건립·소유주라는 별도 경로를 실질적으로 탐색하지 못했다.

실제 읽은 자료는 최신 TomTom 페이지(2025), 2019 INRIX 자료, 2019년에 게시된 다른 교통 기사 등이 섞여 있다. 자료의 발행연도/관측연도/측정 정의를 구분하지 않은 채 비교했다. 최종 출력에는 `202 > 210`이라는 산술 오류와 추측 메모가 그대로 노출됐다. `Regal Cinema`는 이번 fetch 본문 및 rawtree 반환 텍스트의 정확한 문자열 검색에서 발견되지 않았다. 따라서 이미 전달된 정답 영화관을 버린 것으로 단정할 수 없으며, 도시 후보를 확정하지 못한 채 검색 예산을 다 쓴 사례다.

## 정답 판정도 설명 품질까지 보증하지 않음

516번은 이름에 Peter King이 들어가 정답 처리됐다. 하지만 최종 설명은 Kinsey 감독을 Corbin Bernsen으로 놓고 2013년 작품을 Beyond the Heavens로 연결했다. 반환된 Peter Nzioki 본문에는 The Fifth Estate가 있었는데도 이를 제대로 사용하지 않았다. 문제의 띠 조건과 출생연도 모순도 임의로 무시했다. 정확도 70%와 ‘모든 조건을 근거로 검증했다’는 평가는 별개다.

## 적용 순서

1. 실행 시 활성 traversal, 노출 도구, 최종 검증 여부를 명시하고, progressive 평가를 요청했는데 best_first가 실행되는 설정 불일치를 시작 전에 차단한다. 버전 문자열만으로 정책 적용을 판단하지 않는다.
2. d3 요청당 1문항/웨이브 4개/barrier는 유지한다. 기존 progressive 경로를 실제로 활성화해 초기 결과를 먼저 읽고, 선택한 부모의 링크를 필요할 때 평가하며, continue 한 번에 4페이지씩 진행한다. 깊이 5/검색당 50은 상한으로 남긴다. 성능 향상폭은 재실험 전 단정하지 않는다.
3. 후보·조건·근거·모순 상태를 검색 선택과 최종 답변에 반영한다. 구조화 입력만 도입해서는 충분하지 않으며, 746의 ‘대안 후보를 읽고도 불가능한 후보 유지’ 재현을 통과해야 한다. 598은 반복 대신 아직 확인하지 않은 HDS 조건/논문 읽기를 선택해야 한다. 국가·인명별 하드코딩 규칙으로 고치지 않는다.
4. Browser/Jina 반환 성공과 증거 확보 성공을 구별하고, 차단된 유력 원문에는 재읽기/대체 출처 확보 경로를 제공한다. 가능한 라이브러리/Reader 메타데이터와 옵션을 먼저 조사한다. 현재 PDF의 metadata는 title/url뿐이므로 옵션이 이미 충분하다고 단정하지 않는다. 본문 키워드 차단 규칙을 임의로 추가하지 않는다.
5. 주 모델이 증거 없는 설명을 답변에 섞지 않도록 최종 근거 검증을 켠다. 자료의 연도/단위/숫자 조건도 검증 대상으로 둔다. 정답 판정뿐 아니라 조건 위반과 인용 근거도 비교한다.
6. top-k는 우선 현재 페이지 2+4, 청크 4+8을 유지해 traversal 변경 효과부터 분리한다. branch 숫자만 조정하는 것은 best_first에 효과가 없다. 링크 floor는 별도 보정 실험 대상으로 두며, 이번 로그만으로 최적 값을 확정하지 않는다.
7. 먼저 저장 원문/응답을 이용해 598·746·1230의 실패 경로와 516의 설명 오류를 검사하고, 작은 실제 실행에서 첫 근거 반환 시간·총 링크 평가·예산 소진·정답/근거 품질을 확인한다. 그 다음 10문항 전체를 비교한다.

## 분석 도구와 한계

`analysis/inspect_run.py`는 JSON의 필요한 필드만 출력하고 trace JSONL은 한 줄씩 처리한다. `summary`, `metrics`, `steps`, `evidence` 모드를 제공하고 문항·출력 개수·문자 수를 제한할 수 있다. 문항별 집계는 이 폴더의 `qNNNNN.json`, 제한된 근거 발췌는 `_evidence.json`, 연결 오류/링크 많은 페이지는 `request_details.json`에 저장했다.

이번 작업은 로컬 실행 기록과 현재 코드 분석이며, 새로운 모델 요청이나 10문항 재실행은 하지 않았다. 운영 코드는 이 분석 단계에서 수정하지 않았다. 키워드 검색은 후보를 좁히는 수단이며, 단어의 존재를 답의 입증으로 취급하지 않았다.
