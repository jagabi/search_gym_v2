# p12: 검색 전용 메인 + d3 내부 탐색

2026-10-19 구현 및 검증 기록. BM25, 임베딩 검색, 별도 답변 컨트롤러를 추가하지 않았다.
메인은 `web_search(query)`만 사용한다. d3가 페이지 진입, 링크 확장, 독해 페이지와 문서 구간을 선택한다.

## 적용한 변경

| 단계 | 활성 설정 및 동작 |
|---|---|
| 검색 | 최대 10회, 검색당 결과 10개 |
| 초기 진입 | 결과 10개의 제목·snippet을 d3가 평가한 뒤 6개 선택. 평가 실패 시 기존 검색 순서 유지 |
| 링크 확장 | 기존 beam 유지: 부모당 후보 2개, 깊이 3, 후속 깊이당 전체 2개, 링크 하한 0.10, 검색당 최대 10페이지 |
| 페이지 평가 | 첫 부분만 보고 긴 문서를 탈락시키지 않도록 검색 제목·snippet을 함께 제공. snippet은 근거가 아님 |
| 독해 선택 | 원 질문 1개 + 현재 쿼리 1개. 두 번째 페이지는 이미 고른 페이지에 더할 새 단서를 d3가 평가 |
| 중복 | 동일 본문은 검색당 한 독해 슬롯만 사용. 원문·질문·모델이 같은 완전한 독해 판정만 재사용 |
| 긴 문서 | 전체 로컬 청킹 후, 16번들 초과 문서는 구간당 최대 4분할 → 깊이당 전체 2구간 → 최종 최대 4번들 |
| 구간 미리보기 | 원문 제목과 처음·중간·끝 원문 일부, 최대 600토큰. 별도 키워드 점수나 생성 요약 없음 |
| 짧은 문서 | 16번들 이하는 기존처럼 모든 번들 판정 |
| 최종 청크 | 기존 512토큰 청크, 5000토큰 번들, 근거 하한 0.15, 원 질문 4개 + 쿼리 8개, 이웃 청크 1개 유지 |
| 전달 | 전체 16000토큰 중 최대 2000토큰은 URL·제목·snippet·접근/독해 상태. 미검증 탐색 단서로 명시 |
| 요청 | 요청당 판정 1개, 최대 4요청을 보내고 전부 완료된 다음 다음 묶음 전송 |

접근 실패 문서의 제목/저자/식별자로 대체 원문을 찾고, 주어진 희소 단서를 조합하며,
거주지·출생지 및 관측연도·발행연도를 혼동하지 않도록 메인 검색 프롬프트도 수정했다.
정답 인물·정답 URL·문항별 규칙은 생산 코드나 프롬프트에 넣지 않았다.

## 실제 d3 검증에서 제외한 변경

q00516의 저장된 Fifth Estate 페이지 원문을 유지한 채 링크 72개를 재평가했다.
배우와 배역, 이미 알려진 감독 등을 명시한 새 링크 프롬프트는 정답 인물 링크의
점수를 0.43979 → 0.62871로 올렸지만, 전체 순위를 11위 → 19위로 낮췄다.
72요청, 4개씩 처리, 총 36.718초였다. 이 프롬프트는 채택하지 않았다.
최종 `link_question()`은 저장된 기존 실행의 링크 프롬프트와 동일함을 확인했다.

`p12_all_links_replay.json`은 **제외한 후보 프롬프트**의 결과이며 최종 p12의 성적이 아니다.
`p12_link_replay.json`, `p12_link_roles_replay.json`도 중간 후보 프롬프트 기록이다.
`analysis/replay_navigation_links.py`는 현재 생산 프롬프트로 저장 페이지의 링크 판정을 재현하는 도구다.

## 기존 오답과의 연결 및 남은 한계

- 57·598: 접근 실패를 단순 실패 건수 대신 문서별 단서로 반환하여 식별된 문헌의 대체 원문 검색을 지원한다. 접근 자체가 복구된 것은 아니다.
- 516: 알려진 인물의 유사 소개 두 개가 읽기 슬롯을 차지하지 않도록 독해 선택을 바꿨다. 정답 링크가 top-2 아래였던 문제는 **해결 확인되지 않았다**. 링크 프롬프트 실험은 위 이유로 원복했다.
- 746: 검색 7~10위도 진입 평가에 포함하고, 추측한 지명보다 주어진 희소 단서 조합을 우선하도록 검색 프롬프트를 바꿨다. 필요한 NYC 원문에 실제로 도달하는지는 재실행해야 한다.
- 1230: 역사적 연도·측정값을 유지하는 검색 지침과 동일 본문 중복 독해 방지를 적용했다. 올바른 역사 자료 선택 및 정답 도출 여부는 미측정이다.

구간 미리보기는 문서 전체를 대표하는 완전한 색인이 아니다. 제목 없는 구간이나 표본 사이에만
있는 근거는 놓칠 수 있다. 이 방식은 정렬된 키에 대한 이분 탐색이 아니며, d3가 판단하는
다중 구간 beam 탐색이다. 실패한 판정은 낮은 관련도로 바꾸지 않고 불확실 경로 하나를 남긴다.
지역 최선 선택이 전역 최선이나 완전 탐색을 보장하지는 않는다.

## 검증

`python -m unittest discover -s tests -p 'test_raw*.py' -q`: **69개 통과**.
기존 55개와 신규 14개: 기본 설정에서 메인은 검색만 10회 사용, 실제 4요청 wave 유지,
검색 7위 진입, 문서별 실패 단서 반환, 중복 본문 독해 슬롯 보충, 판정 재사용 무효화,
두 목표의 문서 구간 유지, 실패 구간 보존, 실제 Docling 청킹 후 끝부분 원문 반환 등을 확인했다.

합성 문서의 256번들은 구간 28개 판정 후 최대 4번들로 좁혀졌고, 두 목표가 있는 처음/끝을 모두 유지했다.
이는 선택 로직에 대한 테스트이며 실제 모델 정확도 개선의 근거로 취급하지 않는다.
전체 10문제 벤치마크는 재실행하지 않았다. 정확도 상승이나 문제당 20분 달성은 아직 주장할 수 없다.
