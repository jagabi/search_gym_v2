# d3 입력·읽기 판단·깊이 파일럿 결과

2026-10-21. 제품 코드와 설정은 수정하지 않았다. conda `search`의 Python 3.11로 분석 스크립트를 실행했고, 설정된 Jina와 d3만 사용했다. 메인 GPT-OSS, 채점 모델, 검색 API, 전체 벤치마크는 호출하지 않았다. `p19_marginal`은 분석 폴더 이름이며 제품 버전은 p18 그대로다.

## 결론

1. 링크 평가에 해당 링크가 등장한 원문 문단과 해당 목적지 URL만 주는 방안은 유망하다. 516의 필요한 링크가 전체 77개 중 5위에서 1위가 됐다. 기존 확인 경로 세 개에서는 필요한 링크가 모두 1위를 유지했다.
2. 새 고정 질문 세 시나리오에서도 필요한 원문 근거 반환을 유지하면서 총 d3 입력 토큰이 약 34.1% 줄었다. 호출 수는 줄지 않았다.
3. 그러나 516을 Kinsey부터 실제로 탐색하면 The Fifth Estate까지 도달한 뒤 출연진을 읽지 않고 RETURN한다. 따라서 정답 후보 반환이나 전체 정답률을 개선했다고 말할 수 없다.
4. 읽기 프롬프트 간결화, 마지막 슬롯 안내 제거, 행동 쌍대 비교, depth 4는 이 실패를 해결하지 못했다. 쌍대 비교는 정상적인 메타데이터 조회에도 퇴행이 있었다. 현재 적용할 근거가 없다.

## 비교한 방안

링크 점수 비교는 **같은 저장 상태와 전체 링크 77개**를 사용했다. 정답 이름이나 필요한 링크를 추가 입력하지 않았다. 기대 목적지는 결과 집계에만 사용했다.

| 방안 | 필요한 영화 링크 순위 | d3 입력 토큰 | 결과 |
|---|---:|---:|---|
| 현행 | 5 | 527,363 | 자식 폭 2에서 탈락 |
| 현행 첫 문장의 목표를 현재 검색어→원래 질문으로 변경 | 4 | 527,286 | 여전히 탈락 |
| 짧은 추가 근거 기준 | 11 | 524,976 | 악화 |
| 현행 문구 + 링크별 원문·목적지로 입력 축소 | 1 | 150,414 | 선택 범위 진입 |
| 추가 근거 기준 + 같은 입력 축소 | 2 | 148,027 | 선택 범위 진입, 현행 문구보다 우선할 근거 없음 |

입력 축소는 `page_text`에서 평가 중인 내부 링크 번호가 등장하는 원문 문단들을 그대로 모으고, `outgoing_links` 대응표에는 해당 링크만 남긴 것이다. 페이지 URL, 검색 lead, 이미 선택한 원문 근거는 유지했다. 평가할 링크 수는 77개 그대로다. 단어 유사도·BM25·도메인 규칙·수동 정답 근거 선택·생성 요약은 사용하지 않았다.

두 입력 필드의 변경을 묶어서 비교한 결과다. 문단 축소와 목적지 대응표 축소 각각의 기여도는 분리하지 않았다. 다른 문단에 있는 필요한 맥락을 잃을 위험도 남는다.

기존 확인 경로:

| 저장 페이지 | 전체 링크 수 | 필요한 목적지의 수정 후 순위 |
|---|---:|---:|
| Python 3.11 What's New 목차 | 7 | 1 |
| Python 3.11 설명→PEP 678 | 47 | 1 |
| Nobel Physics 1921 요약→수상자 facts | 35 | 1 |

Python 목차의 현행 기준은 이번에도 재호출했다. 나머지 두 경로의 대조 순위는 기존 p18 저장 결과이며, 수정 기준은 모두 새로 d3를 호출했다. 이 세 경로는 과거 파일럿에서 사용한 회귀 확인 사례다.

## 새 질문의 전체 트리 비교

고정 URL 진입점으로 entry ranking을 제외했다. 질문, 원문 본문, 최대 depth 3, 문서 읽기 2회, 방문 한도 10개, 자식 폭 2, frontier 폭 2, d3 동시성 4를 유지했다. 모델 호출은 질문당 한 개씩인 기존 HTTP 방식이다. 링크 평가 입력 축소 이외에는 제품 판단 함수를 유지했다.

성공은 **선택되어 반환한 원문 청크에 요구한 사실이 있는지**로 검사했다. 메인모델 최종 정답 성공을 뜻하지 않는다.

| 시나리오 | 반환해야 할 사실 | 현행→수정 | 최대 depth | 읽기 수 | d3 호출 현행→수정 | 입력 토큰 현행→수정 |
|---|---|---|---:|---:|---:|---:|
| Nobel Chemistry 1911 요약에서 인물 이력으로 이동 | Marie Curie 출생일·출생지 | 충족→충족 | 2→2 | 1→1 | 97→97 | 261,673→175,827 |
| Python 3.9 설명에서 zoneinfo의 PEP로 이동 | Paul Ganssle·작성일 22-Feb-2020 | 충족→충족 | 2→2 | 2→2 | 241→242 | 828,703→505,535 |
| PEP 615 직접 조회 | Final 상태·작성일 | 충족→충족 | 1→1 | 1→1 | 42→42 | 108,156→108,156 |
| 합계 | | 3/3→3/3 | | 4→4 | 380→381 | 1,198,532→789,518 |

관찰 시간은 각각 52.20→38.61초, 167.70→129.95초, 20.70→22.03초였다. 원문 캐시 사용 여부가 일부 다르고 서버 부하도 고정하지 않아, 이를 보장된 속도 향상률로 해석하지 않는다. 입력 토큰 감소와 호출 수는 실제 기록이다.

세 시나리오는 두 주제를 사용하며 PEP 경로 조회와 직접 조회는 같은 문서를 공유한다. 따라서 독립 문제 세 개의 대표 표본이나 다른 데이터셋의 평가 결과가 아니다. 하나의 올바른 URL을 주었기 때문에 초기 검색·검색 결과 선별 능력도 측정하지 않았다.

## 516: 링크 개선 이후에도 실제 반환은 실패

시작 URL은 로그에도 있었던 Kinsey 영화 페이지 하나다. 현재 검색어는 원래 로그의 `"Kinsey" film director 2004`, 원래 문제는 그대로 사용했다.

수정 입력을 사용한 실제 방문:

```
Kinsey (depth 1, 읽음)
  → Bill Condon (depth 2, 확장)
    → The Fifth Estate (depth 3, RETURN)
    → David Koepp (depth 3, RETURN)
```

다른 depth 2 형제는 Variety의 Kinsey 관련 기사였고 RETURN했다. 5개 페이지 방문, 읽기 1회, d3 246회, 입력 608,843토큰, 관찰 시간 135.52초였다.

The Fifth Estate의 최초 d3 관찰 범위에는 Peter Nzioki와 Oscar Kamau Kingara 배역이 있었다. 그러나:

- direct_answer: 0.2740
- query_answer: 0.4416
- RETURN: 0.6545

READ가 RETURN에 졌다. 선택 원문에는 Peter Nzioki가 반환되지 않았다. 읽기 예산이 한 번 남아도 가지가 닫혔다. 이는 문서 접근 실패나 본문 앞부분에서의 이름 부재로 설명할 수 없다.

### 깊이 한도만 4로 변경

다른 한도와 판단 기준은 유지했다. 결과는 5페이지, 읽기 1회, 실제 최대 depth 3으로 동일했다. The Fifth Estate에서 RETURN 0.6390, EXPAND 0.6280, READ 0.4393으로 RETURN했다. d3 호출은 248회, 입력 623,026토큰이었다.

즉 이 경로에서 한도를 늘리는 것만으로 더 내려가지 않았다. 관찰 시간이 126.75초였다는 차이는 캐시·서비스 지연이 달라졌기 때문일 수 있으며 깊이 증가의 성능 이득으로 세지 않는다.

## 읽기·종료 판단의 추가 파일럿

### 짧은 읽기 질문 / 마지막 슬롯 안내 제거

영화 페이지, 다른 인물 페이지, 출생 정보 페이지, 직접 조회 메타데이터 페이지의 실제 저장 상태를 재평가했다.

The Fifth Estate에서:

| 기준 | max(READ 두 값) | RETURN | 읽기 선택 |
|---|---:|---:|---|
| 현행 | 0.442 | 0.655 | 실패 |
| 마지막 슬롯 안내 제거 | 0.474 | 0.686 | 실패 |
| 짧은 읽기 질문 | 0.394 | 0.655 | 실패 |
| 짧은 질문 + 안내 제거 | 0.361 | 0.686 | 실패 |

다른 인물은 모두 RETURN, 정상 출생 정보와 메타데이터 페이지는 모두 READ를 유지했다. 성공 사례 보존과 별개로 목표 실패를 고치지 못했으므로 채택하지 않는다. 마지막 슬롯에서 사용할 수 없는 확장을 언급하는 문구는 부정확하지만, 이를 제거하면 이번 실패가 해결된다는 가설은 지지되지 않았다.

### 행동을 직접 비교

각 행동에 독립적인 확률을 준 뒤 비교하는 대신, 두 행동 중 어느 쪽이 더 유용한지를 질문했다. 세 행동이 가능한 경우 각 쌍의 승리 확률 합으로 순위를 비교했다. 제품에 이 결정을 적용하지는 않았다.

- 영화: READ가 RETURN보다 낫다는 값 0.432 → 여전히 RETURN.
- 다른 인물: RETURN 유지.
- Bill Condon 중간 노드: EXPAND 유지.
- 출생 정보: READ 유지.
- 정상 PEP 메타데이터: READ 대신 RETURN으로 퇴행.

따라서 독립 점수의 척도 문제만 제거하면 해결된다고 볼 수 없다. 이 쌍대 비교 기준은 배제한다.

### 원래 질문의 문장을 각각 평가

문제를 새로 해석하거나 수동 중간 목표를 쓰지 않고, 원래 질문을 문장 단위로 나누어 모두 같은 기존 읽기 질문에 넣었다. 전체 원래 질문은 상태에 유지했다. 정답, 모델 reasoning은 주지 않았다.

- 영화의 최고 문장 점수는 2013년 출연작 단서의 0.571이었다. 기존 RETURN 0.655보다 낮아, 이 값만 기존 행동 비교에 넣어도 읽기가 선택되지 않는다.
- 다른 인물 최고값은 0.329.
- Bill Condon의 2013년 작품 단서는 0.788. 이 값으로 READ를 올리면 중간 감독 페이지를 먼저 읽어 마지막 슬롯을 소비할 수도 있으므로, 곧바로 전체 경로 개선으로 해석하면 안 된다.
- 정상 출생 정보·메타데이터는 높은 점수를 유지했다.

복잡한 문제의 읽기 대상은 2개에서 6개 질문으로 늘어 비용도 커진다. 전체 경로에 적용하지 않았고, 단순한 max pooling을 제품에 반영할 근거는 없다.

## 구체적인 반영 후보와 보류 사항

현재 반영 후보는 **개별 링크 평가의 입력 범위 축소** 하나다. 페이지 행동 판단과 원문 청크 선택은 그대로 두고, 링크마다 원래 문단들과 해당 URL을 사용한다. 문서별 예외처리나 추가 기능 없이 기존 d3 입력 값과 링크 평가 실행 방식의 변경으로 구현할 수 있다.

다만 이를 바로 정답률 개선 버전이라고 묶어서 적용하지 않는다. 문서 전체 맥락이 필요한 링크, 표·목록에 있는 링크, 같은 링크의 여러 문맥에서 회귀가 남을 수 있다. 이번에 확인한 것은 제한된 경로에서의 순위 개선·입력량 감소다.

읽기/종료는 별도의 미해결 문제다. 추가 근거라는 문구를 늘리는 방안, 읽기 질문을 짧게 하는 방안, 깊이 확대, 직접 행동 비교가 충분하지 않았다는 실제 결과를 남긴다. 메인모델은 이번에 실험하거나 수정하지 않았으므로 그 변경 효과를 주장하지 않는다. 598·746·1196·1230 해결도 검증하지 않았다.

## 원시 기록과 재현

원시 요청·응답, 전체 순위, 전체 경로, 반환 원문은 `analysis/pilots/p19_marginal/`에 있다. `audit.json`은 반환된 원문만 검사한 집계다. `action_summary.json`, `pairwise_summary.json`, `clause_summary.json`에 실패한 판단도 남겼다.

초기 일괄 링크 비교는 분석 스크립트의 300초 한도로 중단됐다. 완료된 비교는 보존하고 이후 다른 파일로 이어서 실행했다. 문단 추출 첫 시도는 내부 링크가 두 가지 표기로 저장된 것을 처리하지 못해 32개 평가 뒤 중단됐다. 번호 토큰 자체를 찾도록 분석 스크립트를 고쳐 77개 전체를 다시 평가했다. 중단된 부분 결과를 완성된 비교로 집계하지 않았다. 초기 집계의 slots dataclass 직렬화 오류도 분석 스크립트에서 수정했다. 제품 또는 d3 서비스 오류로 세지 않는다.

```cmd
conda activate search
python analysis/pilot_marginal_routes.py --cases bill --variants current original marginal focused_current focused_marginal
python analysis/pilot_marginal_paths.py --cases chemistry pep615 direct --variants current focused_current --timeout 180
python analysis/pilot_marginal_paths.py --cases bill --variants focused_current --timeout 240
python analysis/pilot_marginal_paths.py --cases bill --variants focused_current --depth 4 --timeout 240
python analysis/pilot_marginal_actions.py
python analysis/pilot_pairwise_actions.py
python analysis/pilot_clause_gain.py
python analysis/summarize_marginal_pilots.py
```

재현 스크립트는 같은 이름의 분석 결과 파일을 새로 쓴다. 중단된 링크 비교를 이어갈 때는 `--resume`으로 완료된 조합을 건너뛸 수 있다. 본문 캐시가 있으면 재사용하고, 없으면 Jina로 수집한다. 전체 벤치마크 실행 명령은 이번 작업 범위에 포함하지 않는다.
