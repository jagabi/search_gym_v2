# v66 level 탐색 복구 + 현재 query split 유지 (2026-10-13)

사용자 요청에 따라 기본 jevtree 실행을 `level`, entries=3, branch=3, depth=3으로 변경했다.
기준은 300문항 44정답 실행의 커밋 `579ad75c`다. 현재 코드에 보존되어 있던 level 경로를 사용하며 LDS 코드를 삭제하지 않았다.

유지 사항:
- JEV `direct_answer`(원질문), `query_answer`(현재 검색쿼리), query 우선 링크 평가.
- reader 직접 정답 2개 + 쿼리 답 4개, 점수 하한 .15, 중복 제거, 미사용 슬롯 미이월.
- reader 입력은 원질문·현재 쿼리·페이지 URL·한 페이지 본문. 메인 reasoning/이전 검색 기록은 전달하지 않음.
- 본문은 공통 fetch 처리에서 최대 32,768토큰으로 제한. JEV만 추가로 앞 5,000토큰을 사용하며 reader에는 이 짧은 발췌를 대신 전달하지 않음.
- reader 출력은 자유서술, 출력 상한 8,192토큰. 선택된 최대 6문서에 각각 독립 호출.
- 로컬 Jina 실제 fetch 서버의 시작 검사, 공개 주소/연결 실패 차단, 동시 요청 상한 50.
- 원문 fetch 로그를 LDS뿐 아니라 level에서도 저장하도록 유지.

탐색 차이:
- 시작점에 .15 점수 하한을 다시 적용한다.
- 각 깊이의 페이지 평가를 마치고 부모별 자식을 확장한다. 부모 하나의 최대 3자식 fetch는 병렬이고, 부모들은 기존 v66처럼 순서대로 처리한다.
- 정상 확보 문서는 최대 3+9+27=39다. 실패/중복 보충은 부모별 최대 2×width 후보까지 시도하므로 총 요청 수가 39를 넘을 수 있다.
- LDS 전용 40-fetch 예산은 level에서 사용하지 않는다.

이 설정은 v66 전체 재현이 아니라 **v66 탐색 + 현재 JEV/reader 의미 체계 + 로컬 fetch** 조합이다. 과거 44/300 성능이 보장되는 것은 아니다. 이 변경에서는 벤치마크/모델 호출을 실행하지 않았다.
