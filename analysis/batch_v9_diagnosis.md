## q00026: 읽은 후보가 반환에서 사라짐

정답은 Abdisalam Ibrahim. v9 첫 Wikipedia 독해 원문에 다음 행이 있었다.

`Abdisalam Ibrahim – Manchester City – 2009–10[b SOM]`

그러나 추출 응답은 모든 조건을 만족하는 선수가 없다고 설명하고 Next links: None,
Expand: no로 끝냈다. 이 이름은 v9 trace에서 원문 입력/추출 입력에만 있고 후속 반환에는 없다.

## 다음 순서

1. 현재 v9로 300문항 확대 실행은 보류한다. 절감은 확인됐지만 목표한 복수 선택은 미검증이다.
2. 검색/fetch/judge 없이 저장된 선택 입력을 사용하는 소규모 실모델 진단에서 복수 native
   호출이 가능한지 먼저 확인한다. 명백히 상보적인 두 출처를 고르는 형식 진단과 실제
   선택 입력을 구분하고, 진단에서 복수 호출을 요구한 것을 벤치마크 정책으로 쓰지 않는다.
3. 일반 응답 마무리는 전용 단계 프롬프트로 정리한다. 원문 근거는 기존대로 별도 보존하고
   새로운 상태 관리 호출을 추가하지 않는다. 저장된 실패 문맥으로 정상 응답률을 확인한다.
4. 원문 추출에서는 후보·확인된 관계·미확인 조건을 남겨야 한다. 전체 질문을 한 페이지가
   완결하지 못한다는 이유로 후보 자체를 버리는 규칙을 피한다. q00026 같은 개발 사례는
   후보 보존의 작동 검사에 쓰고 독립적인 성능 향상의 증거로 쓰지 않는다.

복수 native 호출이 작동하지 않는다면 현재 구조를 배치라고 유지해서는 안 된다.
그때는 제한적인 순차 선택 복귀와 DS 전용 URL 배열 인자 도입 중 하나를 명시적으로
선택해야 한다. 후자는 도구 인터페이스 변경이므로 몰래 폴백으로 추가하지 않는다.
