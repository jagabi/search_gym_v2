# p34 결과 진단

대상은 p33(20261022-1705)과 p34(20261022-1829)의 동일 진단 10문항이다.
저장 로그만 분석했다. 추가 모델·Reader 호출이나 운영 코드 수정은 하지 않았다.

## 실제 변경 범위

config.json의 agent/explorer/model/items/judge 설정과 두 프롬프트 파일은 같다.
변경한 것은 beam의 최종 문서 2개 재선별 제거, 통계 산출, 캐시 버전이다.
청킹, 4096토큰 입력, 방문·확장 예산, PPLX 질문과 메인 프롬프트는 그대로다.
단일 question 통합은 앞선 파일럿에만 적용했다. p34는 여전히 direct 4묶음을 먼저 고르고 query 8묶음을 덧붙인다.

## 516: 높은 점수의 출연진 묶음이 예산에서 탈락

마지막 검색은 `Bill Condon film 2013 drama thriller`이다.
Bill Condon(depth1) → The Fifth Estate(depth2)로 진입했고, Peter Nzioki의 출연진 행이 있는 bundle1도 평가했다.

|실제 우선순서|문서·묶음|direct|query|반환|
|---|---|---:|---:|---|
|direct 1|영화 bundle0|.86308|.96998|O|
|direct 2|감독 bundle2|.83773|.95394|O|
|direct 3|감독 bundle0|.73984|.98862|O|
|direct 4|감독 bundle1|.68952|.99016|O|
|후속 후보|출연진 bundle1|.67571|.90002|X|

quota_select는 direct 정원을 먼저 나열한 뒤 아직 선택되지 않은 query 묶음을 나열한다.
_read_rows는 이 순서대로 전체 묶음을 넣으며 겹침 병합 후 토큰 예산을 검사한다.
앞의 네 묶음이 13984토큰을 사용하여 본문 예산14000 중 16토큰만 남았다.
출연진의 query가 .900이어도 반환되지 않는다. floor .15 때문이 아니다.

같은 입력을 이전 문서 필터로 재생해도 영화+감독이 선택되고 같은 네 묶음이 반환된다.
따라서 이 검색의 손실은 문서 필터 제거로 새로 생긴 것이 아니라, 남아 있던 묶음 순서·예산 병목이다.
p33의 특정 경로에서는 문서 필터 제거로 단서가 살아났지만 다른 경로에서도 회수된다고 검증한 것은 아니었다.

### 링크에서도 인물 후보가 밀림

Peter Nzioki 링크는 실제 평가됐으며 .17616이다.
선택된 상위 두 링크는 Deadline 기획 기사 .87146, David Thewlis .85644이다.
인물 링크는 .10을 넘지만 순위에서 밀린다. floor를 낮춰도 해결되지 않는다.
반환의 6-3/6-4와 별도로 7-3/7-4에서도 손실이 관측된다.

## 신규 오답326: 문서 필터 유무에 따른 반환 차이가 없음

이번 10개 검색의 문서와 점수를 고정해 이전·새 반환 방식을 재생했다.
모든 검색에서 반환 묶음의 추가·제외가 0개였다.
본문이 반환된 것은 고층 건물 목록 검색 한 번이고 9번은 빈 근거였다.
전 실행 마지막에 찾은 Fran Manushkin 기사에 이번에는 도달하지 않았다.
미확인 1973, New York, elephants/giraffes가 검색 조건에 들어간다.
정답 본문을 확보했는데 새 반환 방식이 버린 사례는 아니다. 주요 관측 단계는 1과2이다.

## 신규 오답1196: 방식 차이가 생기기 전에 Ujjain으로 고정

첫 검색부터 전 실행과 다르고, 첫 결과는 Indore/Ujjain으로 이어진다. 두 번째 검색부터 Ujjain을 고정한다.
첫 번째·두 번째 반환 묶음은 이전 필터를 복원해도 동일하다.
방식 차이는 세 번째·아홉 번째 검색에서만 발생한다.
따라서 초기 Ujjain 고정을 새 방식이 추가한 본문 때문이라고 설명할 근거가 없다.

첫 Indore 원문에 나오는 Indreshwar Mahadev Temple의 도시명 유래를 최종 답변에서 Ujjain에 붙인다.
다른 도시의 사실을 연결하는 8-1 오류가 관측된다. 3.25% 인구증가 주장도 일치하는 반환 근거를 확인하지 못했다.

네 번째 검색의 Scribd 후보 제목은 `Thiruvananthapuram's 3.25% Growth Rate`이다.
그러나 snippet은 Tehri Garhwal의 이주 자료라고도 서술하므로 정답 근거라고 확정할 수는 없다.
다운로드는 성공했지만 inspect=.09260으로 floor .15 미만이어서 본문 검사에 들어가지 않았다.
이는 4-2/4-3의 검사 전 손실이다. 검사 후 문서 필터를 제거해도 구제되지 않는다.

## 시간 증가

메인 LLM 요청→응답 합계는244.1→320.7초, RawTree 처리 합계는1667.5→1990.6초다.
검색 API 처리 등도 있으므로 두 값의 합이 전체 실행시간과 일치하지는 않는다.
PPLX는1213회 모두200이며 평균 .868초, 최대8.235초로 대규모 timeout 장애는 아니다.

117번의 두 번째 검색은149.6초다.
`"two of each" farm 139 acres"` 검색의9위 USDA PollinationHandbook PDF fetch가123.7초 걸렸다.
그 페이지의 inspect=.00491이어서 본문을 읽지도 않는다.
검색10개 전체 다운로드 장벽이 가치가 낮은 장시간 fetch에도 기다리는 사례다. 이 설계는 p33부터 존재했다.

## 다음 검증 순서

1. temperature를 고정해 처음부터 다른 쿼리가 나오는 변동을 줄인다. 0도 외부 검색·연산의 완전 재현을 보장하지는 않는다.
2. 516의 동일 입력으로 direct→query 고정 반환 순서와14k 본문 배분을 검증한다. 문서 필터 복원만으로는 해결되지 않는다.
3. 단일 question을 운영에 넣는다면 후단의 direct4/query8 정원과 순서도 일관되게 바꿔야 한다.
4. 단일 점수도 감독 소개를 더 높게 평가할 수 있으므로 통합만으로 출연진 회수가 보장되는 것은 아니다.

확정한 구조적 병목은 이미 충분한 점수를 받은 묶음이 반환 순서·예산으로 사라지는 점이다.
정답률 하락의 전부가 이 하나의 변경 때문이라고는 확정하지 않는다.

## 재생 방법과 로그 주의

새 오답326/1196과516의28개 검색에서 운영 _read_rows를 저장 청크·점수로 재생했다.
현재 방식의 반환 묶음 ID와 실제 로그가28개 검색 모두 일치하는지 assert로 확인했다.
이전 방식은 동일 검사 페이지에만 문서2개 quota를 다시 적용했다. 메인 모델의 이후 반응은 재실행하지 않았다.
원문·재생 결과는 counterfactuals.json 및 q번호_s검색번호_*.txt에 있다.

JSONL은 실제 개행으로 분리했다. splitlines()는 본문 속 유니코드 구분자까지 나누므로 사용하지 않았다.
598번도 실제860행 모두 정상 JSON이다. 초기 도구에서 보인 손상 경고는 분석기의 줄 분리 문제였다.
