# p21: 구간 우선 링크 확장

제품 버전 `raw-browser-d3-navigation-docling/21`. 사용자 요청에 따라 기존 beam 확장의 d3 입력과 트리 확장 방법만 수정했다. 새 도구·모델·API·검색 기능은 추가하지 않았다. 메인모델의 도구, 프롬프트, reasoning 전달 정책은 유지했다.

## 실행 흐름

1. 다운로드한 원문을 기존 청커의 Markdown parser로 제목 계층·원문 구간으로 나눈다. CPU 작업이며 원문 전체를 모델에 전송하지 않는다. 코드 블록 안의 제목 문자열은 제목으로 해석하지 않는다.
2. 기존 URL 유효성·방문·중복 필터를 통과하는 링크가 있는 구간들을 인덱싱한다. 배너/메뉴용 도메인 규칙이나 키워드 필터는 추가하지 않는다. 페이지 action 입력에는 최대 600토큰의 원문 제목·위치 표본을 탐색용으로 추가한다. 앞 5,000토큰 밖의 구간도 탐색 후보가 될 수 있다.
3. 기존 READ/EXPAND/RETURN 판단으로 EXPAND가 선택된 페이지에만 구간 판단을 수행한다. 구간이 많으면 최대 4분기·전역 beam 2로 연속 범위를 좁힌다. 최대 4개 구간 후보까지 좁힌 후 개별 구간을 판단하고 최종 최대 2개 구간을 선택한다. 기존 `jev_region_branch`, `jev_region_beam`, `jev_leaf_bundles`, `jev_region_tokens`를 재사용한다.
4. 선택한 구간 안에서만 링크별 d3 평가를 수행한다. 구간·링크 모두 기존 `jev_link_floor=0.10`을 사용한다. 판단 실패는 0점으로 바꾸지 않고 unknown으로 기록하며 같은 beam 안에서 한 불확실 경로를 보존한다.
5. 기존 자식 폭·전역 frontier 폭으로 실제 URL을 방문한다. 문서 내 구간 선택은 웹 depth를 증가시키지 않고, URL 방문만 depth를 증가시킨다.

메뉴도 d3가 필요한 기록으로 이어진다고 판단하면 선택할 수 있다. 하나의 거대한 제목 없는 구간에 링크가 몰려 있으면 링크 평가 수 절감이 작을 수 있다.

## 링크 입력

각 링크에는 문서 제목, 원문 구간 제목 경로, 링크를 포함한 원문 문단, 해당 목적지 URL, 실제 탐색 경로, 이미 선택해 반환한 원문 청크를 제공한다. 다음 자식의 탐색 경로에는 부모에서 들어온 구간과 anchor를 보존한다. 경로는 이동 기록이며 사실 관계의 증거가 아니라는 점을 명시한다. 생성 요약·새 계획·메인 reasoning은 제공하지 않는다.

긴 링크 문단은 실제 내부 링크 번호를 중심으로 원문 토큰 범위를 제한한다. `link_1`과 `link_10`을 구별하고, 현재 페이지 입력 한도 5,000토큰을 유지한다. 같은 목적지가 여러 선택 구간에 있으면 문맥별 점수를 평가한 뒤 가장 높은 점수의 구간 경로를 보존한다.

기존 페이지당 최대 링크 평가 수 300개는 늘리지 않았다. 두 선택 구간에 링크가 많으면 번갈아 포함해 한 구간이 한도를 독점하지 않게 한다. 기존 공유 HTTP wave 제한 4를 사용하고, 링크 판단 wave 실패 시 완료된 결과만 보존하고 이후 wave를 중단한다.

## 유지한 예산과 원문 처리

진입 6개, 최대 depth 3, 방문 10개, 문서 읽기 2회, 자식 폭 2, frontier 폭 2, 검색 10회를 유지한다. PDF·CSV 백엔드 처리, 청크·bundle 선별, 반환 원문 예산도 유지한다. 구간 표본 자체는 정답 근거로 반환하지 않는다.

전체 원문의 구조 인덱싱과 제한된 위치 표본은 탐색을 위한 관찰이다. 모든 청크를 평가하거나 정답 근거로 읽었다는 뜻이 아니다. 표본에 없는 근거나 잘못 선택된 구간을 놓칠 가능성은 남는다. 구간 선택이 추가되므로 HTTP 호출량과 전체 지연이 반드시 줄어드는 것도 아니다. 실제 d3 판단 결과와 호출량을 서버에서 확인해야 한다.

## 로그와 검증

- `rawtree.link_sections`: 원문 구간의 제목·위치·링크 수.
- `rawtree.link_regions`: 범위/구간 판단 점수와 선택, unknown 여부.
- `rawtree.links`: 실제 평가한 링크와 구간 경로.
- `reader_stats.link_region_evaluations`, `link_sections_selected`: 구간 선택 비용·개수. 기존 `links_scored`와 전체 d3 호출/토큰을 함께 비교한다.

오프라인 검증: 기존 RawTree 81개, 새 구간 탐색 10개, PDF·CSV 연결 4개 통과. 메모리 원문·가짜 HTTP·가짜 d3만 사용했다. 실제 Jina·d3·검색·메인모델·채점 호출이나 벤치마크/파일럿 실행은 하지 않았다. 테스트는 제어 흐름과 한도를 검증하며 실제 모델의 판단 정확도나 정답률 개선을 입증하지 않는다.

새 검증은 앞부분 밖의 부록 경로, 선택되지 않은 메뉴 구간의 링크 평가 생략, 메뉴도 필요한 경우 선택 가능, 부모 구간·실제 경로의 자식 전달, 많은 구간의 계층 선택, leaf 한도가 beam보다 작을 때 종료, 반복 URL의 최선 문맥 보존, unknown 경로 보존, 원문 구조 손실 방지, 정확한 링크 번호/토큰 한도, 두 구간 사이의 기존 300링크 한도 분배를 확인한다.

## 서버 실행

```cmd
conda activate search
python test.py --method jevtree --model gpt-oss --benchmark browsecomp --path data/browsecomp/test_diagnostic10.json --split test --limit 10 --tag raw_browser_p21_sections --expect-raw-traversal beam --no-cache
```

성능 비교에서는 정답 수뿐 아니라 baseline 정답 유지·추가 정답, 구간/링크 평가 수와 시간, 실제 depth별 방문/읽기, 링크를 통해 새로 반환한 관계를 구분한다.
